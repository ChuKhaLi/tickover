---
name: setup
description: "Set up Tickover: ask for consent, install the daemon, log in with GitHub, and add Tickover to the status line with a backup of the current one."
---

You are setting up Tickover for this developer. Do these steps in order. Stop and report if any step fails.

1. Show this consent text verbatim to the developer as the `question` of AskUserQuestion — the whole paragraph below, unchanged, followed by "Do you agree?" — with the options "I agree, continue" / "Stop". The paragraph goes inside the question so it is on screen where the developer chooses; do not summarise it or refer to it as "shown above". Do not continue without "I agree, continue". On "Stop", change nothing and end here.

   Tickover will send to its server: your GitHub id (from login), your operating system, the Claude Code version, when each turn starts and stops, counts of file extensions in your project directory (for example "typescript: 40"), and your answers with how long you took and where you answered them (terminal pane, local page, VS Code, or inside Claude Code). Derived on our side, not sent by the plugin: your country, from the IP address of the request, and an activity tier from how many turns you run a week (light under 5, regular 5 to 20, heavy over 20). Buyers can target on both. It will never send prompts, file contents, file paths, repository names, repository owners, or transcripts. Paid questions always show the sponsor and the amount. You can remove everything with /tickover:uninstall. The same three lists, and what happens to them if you delete your account, are at https://tickover.dev/privacy.

2. Check Node: run `node --version`. Require 22.13 or newer, because the daemon keeps its answer queue in `node:sqlite`, which Node has built in from 22.13; on an older Node the install below succeeds but the daemon cannot start. If older, tell the developer that, ask them to upgrade Node, and stop.
3. Install the daemon: run `npm install -g tickover-cli@0.1.4`. The package is `tickover-cli`; the command it installs is `tickover`. Then run `tickover register`; it records the daemon's path so the hooks can restart it.
4. Log in: run `tickover login`. Relay the URL and the one-time code it prints to the developer and wait for the command to finish. It succeeds only when it exits 0 *and* prints "Logged in as <github login>". Any other ending means nobody is logged in. A non-zero exit says why on its last line — relay it as written: a closed account ("This GitHub account cannot be used with Tickover" — deleted or banned, and re-running this will not change it), the developer declining on GitHub, GitHub or the Tickover server refusing the login (say it is a Tickover-side problem), or a server that could not be reached ("Could not start a login", "Could not finish the login"). A zero exit saying the code expired or timed out means the developer never completed the GitHub step. Stop and report in every one of those cases. Do not go on to step 5, which changes the developer's Claude Code settings.
5. Add Tickover to the status line: run `tickover statusline install --script "${CLAUDE_PLUGIN_ROOT}/statusline/statusline.mjs"` (the plugin root is already an absolute path here). It backs up the developer's current status line, keeps showing it above the Tickover line, and changes nothing else in their settings; relay what it prints. Do not read or edit `~/.tickover/config.json` or the Claude Code settings file yourself — config.json holds the developer's login token. If the command fails, stop and report its message.
6. Offer Mods. If the environment variable `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS` is already `1`, skip this step. Otherwise ask with AskUserQuestion, putting this in the `question`: "Answer Tickover questions without leaving Claude Code? This turns on Claude Code's function hooks (Mods), an early-access feature that lets the hooks modules of every installed plugin run, not only Tickover's. With it on, the question appears above the prompt and a number key answers it; without it, you answer in `tickover pane`, the local page or VS Code." Options: "Turn on Mods" / "Not now". On "Turn on Mods", run `tickover mods on` and relay what it prints.
7. Start the daemon now: run `tickover status`; it starts the daemon if needed and prints health. Confirm `loggedIn: true`.
8. Tell the developer: questions appear in the status line while Claude works, at most 10 paid per day, and the status line has already changed — no restart needed. Typing an option's number into Claude Code does not answer: it is sent to Claude as a prompt. Answer with `tickover pane` in a split terminal, with the localhost page (`tickover page` prints its URL and opens it in the browser — the URL carries the daemon token, which is why `tickover status` does not print it), with the Tickover VS Code extension, or, if Mods are on, with a number key while the question is above the prompt (from the next Claude Code session). Note that the extension needs the daemon on the same machine as the editor, so it will report "daemon off" in VS Code Remote, WSL and Codespaces — use the pane or the page there.
